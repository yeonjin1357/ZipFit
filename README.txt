ZipFit / 집핏 — 무료 MVP 0.1

웹사이트: https://zipfit-mocha.vercel.app
배포·운영 방법: DEPLOY.txt

실행
  PowerShell에서 C:\project\ZipFit으로 이동한 뒤:
  uv run uvicorn zipfit.main:app --host 127.0.0.1 --port 8765
  브라우저: http://127.0.0.1:8765
  또는 PowerShell에서 .\run.ps1 실행. 종료는 해당 터미널에서 Ctrl+C.
  처음 실행 시 uv가 Python 환경과 잠긴 의존성(uv.lock)을 준비한다.
  Python 3.11 이상, uv가 필요하다. Node나 API 키는 필요하지 않다.

사용
  1. ‘내 조건 입력하기’를 눌러 기본 정보 → 주거 조건 → 소득·예산 순서로 입력한다.
     모르는 항목은 비워둘 수 있으며 ‘추가 확인 필요’로 남는다. 이전 단계로 돌아가도 입력이 유지된다.
  2. 마지막 단계에서 ‘이 조건으로 공고 보기’를 누른다.
     ‘예시 조건으로 둘러보기’로 2인 신혼가구 예시를 불러와 확인한 뒤 비교할 수 있다.
  3. 기관·희망 지역·검색어·판정 결과를 조합해 공고를 좁힌다.
  4. 상세 화면에서 특별/일반공급 각각의 결과, 근거 PDF 페이지, 보증금·월세 조합을 확인한다.
  5. ‘내 정보 입력 필요’와 ‘공고 조건 검토 중’을 구분해 볼 수 있다. 상세의 부족한 정보 버튼은 해당 입력란으로 이동한다.
  6. 신청은 공식 공고에서 진행한다. 이 앱은 청약을 대신 제출하지 않는다.

실제로 구현한 범위
  LH, SH, GH(임대·매입·본사 게시판), 서울 청년안심주택, 청약홈 임대 유형의 목록 수집.
  기관·지역·제목·접수 일정·조건 판정 필터, 모바일 화면, 원문 및 보관 PDF 확인.
  신청자 생년월일, 혼인, 현재 거주지, 주택 소유 범위, 자동차, 소득·자산, 예산 입력.
  송파해링턴타워 2026-09-22 공고의 청년/신혼 특별·일반공급 4개 유형 기본조건 비교.
  LH 서울 든든전세 2026-10-01 공고의 성년·무주택세대·수도권 거주 기본조건 비교.
  SH 2026-09-30 신혼·신생아 매입임대Ⅱ의 가구 유형·국적·무주택·소득·자산 기본조건 비교.
  SH 맞벌이, 신생아·한부모, 자녀별 자산 완화, 검증 면제 증명서는 선택 입력으로 추가 확인한다.
  소득 초과로 특별공급이 불일치해도 일반공급을 따로 검토한다.
  미입력·미검토·차량 특례·미성년 예외·버전 변경은 자동 탈락 처리하지 않는다.
  조건 비교와 접수 가능 기간, 예산 적합 여부는 별개로 표현한다.
  로그인·결제·외부 AI 호출·프로필 영구 저장은 없다.

현재 한계
  모든 공고에 대한 자격 판정이 완성된 버전은 아니다. 자동 기본조건 비교는 3개 공고/6개 유형.
  ‘기본조건 일치’는 중복신청·특례·증빙을 포함한 최종 자격 확정이나 당첨 가능성이 아니다.
  다른 공고는 목록 탐색과 원문 확인만 지원한다. 총 게시물 수에 결과 발표·비주거 공고도 포함된다.
  제목 기반 모집 후보 분류에는 오분류가 있을 수 있어 안내·미분류 보기 옵션을 제공한다.
  2026-10-01 배포 자료에는 396개 원본 게시물이 들어 있다. 최초 재현 자료는 370개다.
  실행 중 추가 수집 자료가 있으면 data/runtime/catalog.json을 우선 읽는다.
  배포에서는 data/release-catalog.json을 사용하고, 없으면 최초 data/catalog.json을 사용한다.
  최근 목록의 일부 페이지와 과거 표본을 포함한다. 전국 모든 공고·모든 민간사업자 수집을 보장하지 않는다.
  공고의 과거 기준일에 입력 조건이 같았는지 사용자 확인이 필요하다.
  소득은 세전 월평균, 금액은 공고의 합산·공제 방식에 따른 자기 입력이다. 행정정보 조회는 하지 않는다.
  검토 후 24시간이 지났거나 목록 정보가 바뀌면 판정 결과를 ‘추가 확인 필요’로 보류한다.
  변경이 감지된 공고의 이전 일정은 접수 중·예정으로 표시하지 않는다. 재확인이 필요한 금액은 보관본 기준임을 표시한다.
  확인된 LH 내부 정정 연결과 서울 청년안심주택→SH 정정 원문 연결을 제공한다. 제목 유사성만으로 자동 합치지는 않는다.
  목록 새 수집만으로 규칙 검토 날짜를 갱신하지 않는다. 첨부·정정·취소를 재검토해야 한다.
  로컬 기본 설정은 127.0.0.1에서 사용한다. 배포 설정은 DEPLOY.txt를 참고한다.

목록 갱신 — 명시적으로 실행할 때만 네트워크 요청
  uv run python -m zipfit.collect --pages 2
  각 목록 경로의 최근 최대 2페이지를 수집해 기존 목록과 합친다.
  LH·청약홈은 최근 약 60일(청약홈은 월 단위), SH·GH·서울은 최근 게시물 페이지 기준이다.
  GH 세 경로, 청약홈 두 임대 유형을 포함해 기본 총 16회 목록 요청을 수행한다.
  실패하면 기존 공고를 지우지 않으며, 출처별 마지막 정상 수집 시각과 오류를 남긴다.
  첫 페이지에서 사라진 공고를 삭제·마감으로 추정하지 않는다.
  원본 응답·요청 조건·SHA256은 data/runtime/snapshots에 보관한다.
  완전한 과거 전수 수집, 상시모집 전수 재확인, 자동 첨부파일 파싱은 아직 없다.
  화면 새로고침은 저장한 목록을 다시 읽는 동작이며 수집 실행을 대신하지 않는다.

검증
  uv run pytest -q
  저장 자료 정합성: uv run python -m zipfit.audit
  보고서 저장: uv run python -m zipfit.audit --output research/phase4/integrity-report.json
  서버 실행 후: uv run python scripts/browser_check.py
  브라우저 검증은 설치된 Google Chrome을 headless로 사용한다.
  UI 검증 파일과 서버 로그는 tmp/ 아래에 저장하며 Git에서 제외한다.
  재현 가능한 최초 카탈로그 생성: uv run python scripts/build_catalog.py
  위 명령은 data/catalog.json만 생성한다. runtime 자료는 유지한다.
  수집 코드·규칙 변경 후 기존 원본 재해석: uv run python -m scripts.rebuild_local_catalog
  이 명령은 원본 응답을 오프라인으로 재생한다. 실행 전 runtime 사본을 남기며 기존 ID와 변경 감지는 보존한다.
  수집·검토 일자를 현재 시각으로 바꾸지 않는다. 공개 목록 수집과 동시에 실행되지 않는다.
  연구용 원본 자료는 research/ 안에 그대로 보존한다.

다음 개발 순서
  1. 첨부파일·정정·취소 재확인 도구를 만들어 규칙이 오래되면 실제 근거를 다시 검토할 수 있게 한다.
  2. 기존 세 공고의 세대 예외·중복신청·순위 조건을 확대하고, SH 날짜별 추가 입력을 일반 가족 입력으로 통합한다.
  3. GH·청년안심 공공임대·청약홈 유형별 판정과 주택별 공급 목록 구조화.
  4. 전체 페이지·과거 진행 공고·마감 안내 연결을 포함한 장기 수집 누락 평가.
  5. 관심 공고 보관과 일정 캘린더 저장을 검토한다. 개인정보 저장은 별도로 동의·설계한다.
