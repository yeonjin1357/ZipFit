ZipFit 배포

Render 무료 웹 서비스용 설정을 render.yaml에 포함한다.
기존 FastAPI 서버와 HTML/CSS/JS를 함께 실행한다. 데이터베이스와 API 키는 필요 없다.

최초 배포
1. GitHub 저장소: https://github.com/yeonjin1357/ZipFit
2. Render에 로그인한 뒤 다음 링크로 Blueprint를 생성한다.
   https://render.com/deploy?repo=https://github.com/yeonjin1357/ZipFit
3. 요금제가 Free인지 확인한다. 설정 파일은 plan: free로 지정되어 있다.
4. 생성한 서비스의 실제 onrender.com 주소를 열어 확인한다.
   계정 권한이 필요한 생성 단계는 Render 로그인 또는 API 인증이 있어야 실행할 수 있다.

배포 구성
- Python 3.13, Linux. requirements.txt는 uv.lock에서 버전·해시를 고정해 내보낸다.
- 실행: uvicorn zipfit.main:app --host 0.0.0.0 --port $PORT --no-access-log
- 헬스체크: /api/health
- ZIPFIT_ENV=production. Render의 RENDER_EXTERNAL_HOSTNAME을 허용 호스트에 등록한다.
- 개인 도메인은 ZIPFIT_ALLOWED_HOSTS에 정확한 호스트명을 추가한다. 여러 개는 쉼표 구분.
- HTTPS 사이트의 같은 출처 요청만 허용한다. 개인정보 입력 본문은 16KiB로 제한한다.
- 요청 본문·프로필을 저장하지 않으며 기본 접속 로그도 끈다.
  호스팅 사업자의 접속·네트워크 로그 정책은 별개다.
- GitHub Actions의 Linux 검증이 통과하면 Render가 새 main 커밋을 배포하도록 설정한다.

공고 데이터
- data/release-catalog.json에 배포 시점의 공개 공고 목록을 함께 보관한다.
- 로컬에서는 data/runtime/catalog.json이 있으면 우선 사용한다.
- Render 무료 인스턴스의 재시작으로 파일 변경이 사라져도 배포에 포함된 목록·PDF는 유지된다.
- 공고 수집은 자동으로 주기 실행하지 않는다. 갱신하려면 로컬에서 다음 순서로 실행한다.
    uv run python -m zipfit.collect --pages 2
    uv run python -m scripts.prepare_release
    uv run pytest -q
  이후 변경된 release-catalog.json을 커밋·푸시한다.
- 목록 갱신만으로 자격 규칙의 검토 시간을 연장하지 않는다. 24시간이 지나면 재확인 안내를 표시한다.

요금·동작 참고
- Free 서비스는 15분 동안 요청이 없으면 정지되며 다음 방문의 시작에 약 1분이 걸릴 수 있다.
- 장기 운영 전에는 최신 요금·사용량 한도와 상시 실행 환경을 별도 결정한다.
- 이 설정은 유료 인스턴스·유료 디스크·DB를 생성하지 않는다.
- 자동 수집·자동 규칙 재검토·관심 공고 알림은 아직 지원하지 않는다.
