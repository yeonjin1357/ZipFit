ZipFit 배포

서비스 주소: https://zipfit-mocha.vercel.app
Vercel 프로젝트: https://vercel.com/yeonjins-projects/zipfit
연결된 GitHub 저장소: yeonjin1357/ZipFit
프로덕션 배포 브랜치: main (Vercel GitHub 연동)

Vercel의 FastAPI 런타임으로 기존 서버와 HTML/CSS/JS를 함께 배포한다.
데이터베이스와 외부 AI API 키는 필요 없다.

최초 배포
1. GitHub 저장소: https://github.com/yeonjin1357/ZipFit
2. Vercel에서 위 저장소를 가져오고 프로젝트의 루트 디렉터리는 저장소 루트로 둔다.
3. Framework Preset은 FastAPI로 자동 감지된다. 명령·출력 디렉터리는 기본값을 사용한다.
4. 무료 Hobby 계정으로 배포한다. 프로젝트 생성은 Vercel 계정 인증이 필요하다.
5. CLI를 사용하는 경우 로그인 후 저장소 루트에서 실행한다.
     npx vercel login
     npx vercel link
     npx vercel git connect
     npx vercel --prod
6. 발급된 실제 프로덕션 주소에서 화면, /api/health, 조건 검색, 공고 PDF를 확인한다.
   PC·모바일 브라우저 검증:
     uv run python scripts/browser_check.py --base-url https://zipfit-mocha.vercel.app
     uv run python scripts/browser_features.py --base-url https://zipfit-mocha.vercel.app

배포 구성
- Python 3.13, Linux. pyproject.toml과 uv.lock으로 의존성을 설치한다.
- 진입점: pyproject.toml의 tool.vercel.entrypoint = zipfit.main:app
- 빌드: python -m zipfit.audit. 공고 구조·출처·PDF 검증에 실패하면 배포를 중단한다.
- vercel.json은 FastAPI, 서울(icn1) 실행 지역, 함수 최대 실행 시간 30초를 지정한다.
- 헬스체크: /api/health
- VERCEL_ENV가 production 또는 preview이면 운영 보안 설정을 적용한다.
- VERCEL_URL, VERCEL_BRANCH_URL, VERCEL_PROJECT_PRODUCTION_URL을 허용 호스트에 등록한다.
  프로젝트 설정에서 시스템 환경 변수 자동 노출을 켜둔다(기본값).
- 개인 도메인은 ZIPFIT_ALLOWED_HOSTS에 정확한 호스트명을 추가한다. 여러 개는 쉼표 구분.
- HTTPS 사이트의 같은 출처 요청만 허용한다. 개인정보 입력 본문은 16KiB로 제한한다.
- 앱은 요청 본문·프로필을 저장하지 않는다.
  호스팅 사업자의 접속·네트워크 로그 정책은 별개다.
- GitHub 연동 후 main에 푸시하면 Vercel이 프로덕션을 배포한다.
  GitHub Actions는 별도로 Linux 테스트와 데이터 검증을 실행한다.
- .vercelignore로 로컬 프로필 환경 파일·임시 파일·런타임 수집 결과를 업로드에서 제외한다.

공고 데이터
- data/release-catalog.json에 배포 시점의 공개 공고 목록을 함께 보관한다.
- 로컬에서는 data/runtime/catalog.json이 있으면 우선 사용한다.
- 공고와 PDF는 함수에 함께 포함한다. 서버 파일시스템에 영구 저장하지 않는다.
- .github/workflows/refresh.yml이 한국시간 03:17/09:17/15:17/21:17에 예약 실행된다.
  GitHub 예약 작업은 지연되거나 비활성화될 수 있으므로 실행 기록을 확인한다.
  Actions의 Refresh housing notices → Run workflow로 수동 실행할 수도 있다.
  테스트 → 수집 → LH 접수 일정 추출 → 원문 재확인 → 정합성 검사 → 검토 보고서 → 카탈로그 커밋 순서다.
  일요일 12:47에는 경로별 6페이지, LH/청약홈 최근 365일의 확대 탐색을 실행한다.
  수동 실행에서 discovery=true를 선택하면 같은 범위로 탐색한다.
  같은 작업의 중복 실행은 막으며, 동시에 다른 커밋이 생겨 push가 거절되면 강제 덮어쓰기 없이 실패한다.
  자동 커밋의 GitHub CI는 다시 실행되지 않으므로 갱신 작업 자체에서 테스트·검사를 실행한다.
- 로컬에서는 다음 순서로 실행한 뒤 변경된 release-catalog.json을 커밋·푸시한다.
    uv run python -m zipfit.collect --pages 2
    uv run python -m zipfit.schedules --limit 80
    uv run python -m zipfit.verification
    uv run python -m zipfit.review --output tmp/review/index.html
    uv run python -m scripts.prepare_release
    uv run pytest -q
- 수집 실패 시 기존 자료와 마지막 성공 시각을 보존하고, 다른 기관의 정상 결과를 게시한다.
  원문 재확인 실패 시 해당 공고의 판정은 보류한다. 마지막 실패 검사 단계는 작업을 실패 상태로 남긴다.
  상세 일정의 통신·구조 오류도 실패로 기록한다. 정정 연결이 감지된 경우는 검토 대기 대상으로 분리한다.
- 목록 갱신만으로 규칙 검토 시간을 연장하지 않는다. 승인한 본문·첨부 전체와 같을 때만 재확인 시각을 갱신한다.
  변경·재확인 실패·24시간 초과 시 판정을 보류한다. 주택 목록 등 비 PDF 첨부도 해시로 확인한다.

검토 대기와 기준본 승인
- tmp/review/index.html은 변경 공고 → 접수 중·예정 미검토 공고 → 일정 미확인 순서로 보여준다.
- GitHub 실행의 notice-review 아티팩트에는 이 보고서와 최신 공개 원문 비교 자료가 7일간 보관된다.
  프로필·인증정보·환경 파일은 포함하지 않는다. 관리용 수정 API나 공개 승인 화면은 없다.
- 변경된 공고는 공식 본문·첨부·정정 연결을 읽고, PDF와 자격 규칙·일정·금액을 함께 수정한다.
  근거 페이지와 결정 내용을 research에 남기고 rule_reviewed_at을 실제 검토 시각으로 기록한다.
  원문 재확인 명령이 만든 data/runtime/verification의 observed를 검토한 후에만
  해당 공고의 reviewed_source로 승인한다. 변경 이유를 해결한 경우 review_invalidated를 해제한다.
  다시 재확인하여 unchanged인지, audit·테스트가 통과하는지 확인하고 배포 자료를 만든다.
  observed를 무조건 복사하는 자동 승인 작업을 추가해서는 안 된다.
- 기준본의 승인 근거: research/phase5/baseline-review.json, review-decisions.json 및 research/phase6/review-decisions.json.
  공급목록 190호는 원본 XLSX 해시·시트/행을 보존한다. 주택 데이터가 바뀌면 이전 원문 승인 기록은 무효다.
  새 목록을 추가할 때 scripts.import_housing.read_units로 해당 검토 형식을 읽고 원본과 대조한 뒤 승인한다.

요금·동작 참고
- 함수는 요청 시 실행되며 처음 호출될 때 지연이 생길 수 있다.
- 장기 운영·상업화 전에는 Vercel의 최신 요금·사용량 한도·Hobby 이용 조건을 확인한다.
- 이 설정은 유료 플랜·DB·유료 추가 서비스를 생성하지 않는다.
- 자동 수집·원문 동일성 재확인을 지원한다. 신규·변경 자격의 자동 승인과 개인별 알림은 아직 없다.
