ZipFit 배포

Vercel의 FastAPI 런타임으로 기존 서버와 HTML/CSS/JS를 함께 배포한다.
데이터베이스와 외부 AI API 키는 필요 없다.

최초 배포
1. GitHub 저장소: https://github.com/yeonjin1357/ZipFit
2. Vercel에서 위 저장소를 가져오고 프로젝트의 루트 디렉터리는 저장소 루트로 둔다.
3. Framework Preset은 FastAPI로 자동 감지된다. 명령·출력 디렉터리는 기본값을 사용한다.
4. 무료 Hobby 계정으로 배포한다. 프로젝트 생성은 Vercel 계정 인증이 필요하다.
5. CLI를 사용하는 경우 로그인 후 저장소 루트에서 실행한다.
     npx vercel login
     npx vercel link
     npx vercel git connect
     npx vercel --prod
6. 발급된 실제 프로덕션 주소에서 화면, /api/health, 조건 검색, 공고 PDF를 확인한다.

배포 구성
- Python 3.13, Linux. pyproject.toml과 uv.lock으로 의존성을 설치한다.
- 진입점: pyproject.toml의 tool.vercel.entrypoint = zipfit.main:app
- 빌드: python -m zipfit.audit. 공고 구조·출처·PDF 검증에 실패하면 배포를 중단한다.
- vercel.json은 FastAPI, 서울(icn1) 실행 지역, 함수 최대 실행 시간 30초를 지정한다.
- 헬스체크: /api/health
- VERCEL_ENV가 production 또는 preview이면 운영 보안 설정을 적용한다.
- VERCEL_URL, VERCEL_BRANCH_URL, VERCEL_PROJECT_PRODUCTION_URL을 허용 호스트에 등록한다.
  프로젝트 설정에서 시스템 환경 변수 자동 노출을 켜둔다(기본값).
- 개인 도메인은 ZIPFIT_ALLOWED_HOSTS에 정확한 호스트명을 추가한다. 여러 개는 쉼표 구분.
- HTTPS 사이트의 같은 출처 요청만 허용한다. 개인정보 입력 본문은 16KiB로 제한한다.
- 앱은 요청 본문·프로필을 저장하지 않는다.
  호스팅 사업자의 접속·네트워크 로그 정책은 별개다.
- GitHub 연동 후 main에 푸시하면 Vercel이 프로덕션을 배포한다.
  GitHub Actions는 별도로 Linux 테스트와 데이터 검증을 실행한다.
- .vercelignore로 로컬 프로필 환경 파일·임시 파일·런타임 수집 결과를 업로드에서 제외한다.

공고 데이터
- data/release-catalog.json에 배포 시점의 공개 공고 목록을 함께 보관한다.
- 로컬에서는 data/runtime/catalog.json이 있으면 우선 사용한다.
- 공고와 PDF는 함수에 함께 포함한다. 서버 파일시스템에 영구 저장하지 않는다.
- 공고 수집은 자동으로 주기 실행하지 않는다. 갱신하려면 로컬에서 다음 순서로 실행한다.
    uv run python -m zipfit.collect --pages 2
    uv run python -m scripts.prepare_release
    uv run pytest -q
  이후 변경된 release-catalog.json을 커밋·푸시한다.
- 목록 갱신만으로 자격 규칙의 검토 시간을 연장하지 않는다. 24시간이 지나면 재확인 안내를 표시한다.

요금·동작 참고
- 함수는 요청 시 실행되며 처음 호출될 때 지연이 생길 수 있다.
- 장기 운영·상업화 전에는 Vercel의 최신 요금·사용량 한도·Hobby 이용 조건을 확인한다.
- 이 설정은 유료 플랜·DB·유료 추가 서비스를 생성하지 않는다.
- 자동 수집·자동 규칙 재검토·관심 공고 알림은 아직 지원하지 않는다.
