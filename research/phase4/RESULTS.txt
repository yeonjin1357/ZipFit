ZipFit 데이터 정합성 및 사용 흐름 개선 / 2026-10-01

이번 작업
- 승인된 화면 디자인을 유지하고 데이터 처리와 조건 비교를 보강했다.
- LH·SH·GH·서울 청년안심주택·청약홈 목록을 경로별 2페이지 다시 수집했다.
  총 16개 요청 모두 정상 응답: LH 200행, SH 20행, GH 49행, 서울 20행, 청약홈 10행.
  기관별 수집 범위는 제한적이며 전수 수집이라는 의미가 아니다.
- 원본 게시물 396개 / 모집 후보 326개. 현재 판정 규칙은 3개 공고, 6개 유형이다.

실제 데이터에서 수정한 문제
1. LH 화성·평택 신혼·신생아Ⅱ의 ‘후순번 모집’을 ‘순번’ 문자열 때문에 결과 발표로
   잘못 제외했다. 모집 후보로 복구하고 회귀 테스트를 추가했다.
2. GH 목록의 마감일·접수상태·시군 정보가 정규화 과정에서 빠졌다.
   보관 원본을 재해석해 마감일 25건을 복구하고 25개 종료 공고를 마감으로 표시했다.
   시군을 확보한 공고는 ‘경기도’ 뒤에 원문 시군도 표시한다.
3. SH ‘입주대상자 발표’와 GH 잔여세대 일반매각을 모집 후보에서 구분했다.
4. 서울 목록의 단일 ‘청약신청일’을 전체 접수 기간처럼 표시하던 표현을 수정했다.
   종료일을 알 수 없으면 기간 전체가 미확인임을 표시한다.
5. 원문 목록이 바뀌면 자격 비교와 이전 접수 일정을 함께 보류한다.
   취소 또는 정정된 검토 공고도 기본조건 일치/불일치로 확정하지 않는다.
6. LH 원본→정정본 외에, 검증 단계에서 확인된 서울 게시물 6624→SH 309925
   정정 원문을 연결했다. 공급 물량이 다른 PDF를 같은 최신 버전으로 취급하지 않는다.
7. 잘못된 날짜·역전된 기간·불완전한 규칙 검토 시각이 있어도 전체 API가 멈추지 않게 했다.
   시간 없는 접수 기간에는 ‘시간 확인’ 안내를 붙이고 한국시간으로 비교한다.

추가한 기능
- ‘내 정보 입력 필요 / 공고 조건 검토 중 / 공고 재확인 필요 / 별도 확인 필요’를 구분한다.
- 상세 화면에서 부족한 정보 버튼을 누르면 해당 단계·입력란으로 이동하고 초점을 맞춘다.
- 규칙을 재확인해야 하는 공고는 카드에 이전 금액을 추천하지 않는다.
  상세에서 보관본 기준 금액임을 명시한다.
- SH 2026년 하반기 신혼·신생아 매입임대Ⅱ 기본조건 비교와 온라인 접수 일정을 추가했다.
  출생일·가족 유형·증명서 관련 추가 항목은 이 공고 전용 선택 입력이다.
- 원본 재해석 도구와 반복 실행 가능한 정합성 검사 명령을 추가했다.
  테스트는 로컬 수집 상태와 관계없이 초기 검증 카탈로그로 재현된다.

검증
- 자동 테스트: pytest 63개 통과. 자격의 1원 경계, 나이·혼인 기준일, 공급유형 대안, 예외와 미입력,
  SH 맞벌이·자녀 자산 완화·증명서 예외, 실제 목록 파서, 정정·취소·잘못된 날짜 포함.
- Chrome: 1440px 데스크톱, 390px 모바일, 360/768/1024px 추가 너비.
  3단계 입력·필터·상세·근거 PDF·부족한 입력 이동·초점·서버 검증 오류·초기화 확인.
  개인 조건은 새로고침 후 사라지고, 가로 넘침과 JavaScript 오류가 없음을 확인했다.

  가격 조합, 기관별 건수, 미입력 프로필·변경 일정 처리의 기계적 검사 결과.
- data-changes.json: 최초 개선 전후 데이터 차이. 최종 정정 연결은 별도로 위에 기록했다.

다음 우선순위
1. 첨부 교체·정정·취소를 재확인하고 운영 검토로 연결하는 절차. 현재 24시간 유효 정책은
   유지되므로 시간이 지나면 판정을 보류한다. 목록 수집만으로 다시 확정하지 않는다.
2. 호별 공급 목록을 구조화해 실제 주택별 보증금·월세 비교 범위를 확대한다.
3. GH·청년안심 공공임대·청약홈의 규칙을 근거별로 확대한다.
4. 관심 공고 보관과 캘린더 저장. 알림은 목록·마감 정확도를 먼저 확보한 뒤 추가한다.
5. 장기적으로 SH 전용 질문을 일반 가족·소득 입력으로 통합해 같은 정보를 반복해서
   입력하지 않도록 한다. 순위·가점과 최종 자격 확정은 아직 지원하지 않는다.
