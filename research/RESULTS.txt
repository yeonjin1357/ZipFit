ZipFit 공고 수집 가능성 검증 — 2026-10-01

판정
LH, SH, GH, 서울 청년안심주택, 청약홈의 공개 웹 경로에서 표본 공고의
목록 → 상세 내용 → 원문 PDF 다운로드를 모두 확인했다.
로그인, 인증서, 브라우저 자동화 없이 일반 HTTP 요청으로 수행했다.
이는 표본에 대한 기술적 접근 검증이며, 모든 공고의 누락 없는 수집이나
신청 자격 판단, 지속적인 운영 안정성까지 검증했다는 의미는 아니다.

실측 결과
- 명시적으로 지정한 HTTP 요청 43회. 원본 응답, 상태 코드, 시각, SHA-256 저장.
- 목록 응답 15개에서 기관별 중복을 제외한 게시물 186개 추출.
  LH 77 / SH 20 / GH 29 / 청년안심주택 30 / 청약홈 30.
  SH는 결과 발표·일반 공지가 섞여 있으며 청약홈 30개 중 임대 유형은 16개다.
  위 숫자는 현재 신청 가능한 주택 수나 전체 공고 수가 아니다.
- 다섯 경로 모두 1·2페이지에서 서로 다른 게시물 ID를 확인했다.
- PDF 8개 다운로드 후 PDF 파서로 열기, 페이지 수, 첫 페이지 텍스트 추출 확인.
- SH HWP 1개는 파일 컨테이너 시그니처 확인.
- LH HWPX 1개는 ZIP 무결성, Contents 구조, application/hwp+zip 형식 확인.
- HWP/HWPX의 자격 조건 텍스트 추출은 수행하지 않았다.

기관별 결과

LH
목록: 성공. 제목, 유형, 지역, 공고일, 목록상 마감일, 상태, 공고 ID 추출.
상세: 성공. 표본: [서울지역본부] 26년 2차 비분양전환형 든든전세주택.
첨부: 모집공고 PDF(24쪽) 및 HWPX 다운로드 성공.
주의: 기본 목록은 날짜 범위와 '공고중' 필터로 제한된다. 이 필터는 화면
안내상 '공고중·정정공고중·접수중'을 함께 포함한다(2차 검증에서 확인).
전체 상태 조회도 별도로 시험했다. 기본 목록 64건과 전체 상태 조회의
검색 결과는 다르며, 이 차이를 접수 중 공고 누락으로 해석하지 않는다.
페이지 번호만 전달한 최초 시도는 HTTP 200인 오류 화면이었다.
공개 페이지에 있는 페이지 이동 폼의 검색 필드를 함께 전달하자 2페이지가
정상 조회됐다. HTTP 200만으로 수집 성공을 판정하면 안 된다.
공식 API: 인증키 없이 시험한 요청은 HTTP 401, SERVICE_KEY_IS_NULL.
인증키를 이용한 API 정상 응답은 아직 검증하지 않았다.

SH
목록: 성공. 주택임대 게시판 두 페이지, 게시물 ID 20개 추출.
상세: 성공. 표본: 2026년 하반기 신혼·신생아 매입임대주택Ⅱ 모집공고.
첨부: PDF(34쪽) 및 HWP 다운로드 성공.
주의: 모집공고, 당첨자 발표, 재계약 심사결과, 서비스 공지가 같은 게시판에
섞여 있다. 모집공고라는 단어만 검색하면 결과 발표 글도 포함된다.
첨부 다운로드 주소는 페이지의 파일 메타데이터와 공개 스크립트에서 확인했다.

GH
목록: 임대주택 게시판 두 페이지 20개, 매입임대 게시판 한 페이지 9개 추출.
상세 및 첨부: 두 게시판에서 각각 성공.
표본 1: GH Care Hub 특화형 매입임대주택 추가모집, PDF 30쪽.
표본 2: 다산진건데시앙 장기전세주택 예비입주자 모집, PDF 30쪽.
주의: 매입임대 표본은 목록의 일정·상태 일부가 비어 있었으며 상세 페이지와
첨부문서에 추가 정보가 있었다. 날짜 공란을 '상시 모집'으로 해석하면 안 된다.
첨부파일은 공개 페이지가 연결하는 GH CDN에서 정상 다운로드됐다.
GH의 다른 모집 경로까지 빠짐없이 포함되는지는 이번 검증 범위에 포함하지 않았다.

서울 청년안심주택
목록: 성공. 최초 HTML의 목록 영역은 비어 있고 공개 화면이 호출하는
POST /youth/pgm/home/yohome/bbsListJson.json 응답에 게시물이 들어 있다.
두 페이지 및 공공임대 필터를 시험해 중복 없는 게시물 30개를 추출했다.
상세 및 첨부: 민간임대와 공공임대에서 각각 성공.
표본 1: 장지역 송파해링턴타워 최초모집공고.
표본 2: 2026년 2차 청년안심주택 공공임대 모집공고.
주의: 이 JSON 경로는 공개 웹페이지의 내부 호출 경로다. 정식 공개 API의
안정성이나 변경 보장을 제공받은 것으로 취급하지 않는다.

청약홈 / 민간임대
목록: 성공. 일반 목록 두 페이지, 공공지원 민간임대 및 민간임대 필터 시험.
중복 제외 30개 게시물 중 임대 유형 16개를 확인했다.
상세 및 PDF: 공공지원 민간임대와 일반 민간임대에서 각각 성공.
표본 1: 서면 지원 더뷰 드림아파트(공공지원민간임대).
표본 2: 안성 공도 센트럴카운티(민간임대).
표본 2는 과거 공고이며 현재 모집 중인 공고로 안내하지 않는다.
주의: 기본 목록은 오피스텔·도시형생활주택·생활숙박시설 등도 포함하므로
주택구분 필터가 필요하다. 청약홈 밖에서만 모집하는 민간사업자는 별도 수집 대상이다.
공식 API: 명세를 읽고 공공지원 민간임대 조회 경로에 인증키 없이 요청했다.
HTTP 401 '인증키는 필수 항목 입니다.' 응답 확인. 인증 후 데이터 조회는 미검증.

기획에 반영할 내용
1. 다섯 경로를 1차 수집 대상으로 삼을 기술적 근거가 확보됐다.
2. 수집기는 목록뿐 아니라 상세 페이지와 첨부파일까지 연결해야 한다.
3. 기관별 날짜·상태 필터와 페이지 이동 방식을 명시적으로 관리해야 한다.
4. 원문과 파일 해시를 저장해 이후 추가·정정 여부를 비교할 기반이 필요하다.
   이번에는 변경 감지기를 구현하거나 정정 사례를 연속 관찰하지 않았다.
5. 공개 웹 수집 가능 여부와 공식 API 사용 가능 여부를 별도로 관리해야 한다.
6. 수집량, 현재 접수 중인 공고 수, 자격 판단 가능한 공고 수는 별도 지표다.

- 정해진 기간의 공고 전체 및 장기·상시모집을 포함한 누락 검증.
- 정정·취소·추가모집, 여러 사이트 중복 게시의 연결 관계 확인.
- 반복 실행 및 장애 시 복구 검증. 페이지 구조 변경과 응답 지연도 측정.
- 수집한 원문에서 일정·자격·주택형·가격을 정확히 추출할 수 있는지 별도 검증.

저장된 증거 재검증 — 네트워크 요청 없음
uv run --no-project --with beautifulsoup4 --with lxml --with pypdf python research/analyze.py

개별 요청 묶음 재실행 예시 — 공개 사이트에 실제 요청 발생
uv run --no-project --with requests --with beautifulsoup4 python research/probe.py research/requests-01.json
같은 요청 ID로 재실행하면 해당 ID의 기존 응답 파일을 덮어쓴다.
기간 비교가 필요하면 research/evidence를 먼저 별도 위치에 보존한다.

이번 작업에서는 서비스 본개발, 신청·접수, 계정 생성, API 활용신청,
기관 연락, 결제, 배포를 수행하지 않았다.
