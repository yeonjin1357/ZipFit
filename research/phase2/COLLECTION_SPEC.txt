ZipFit 수집 설계 초안 v0.2 — 2026-10-01
사용자 목표: 지원 수집처의 공고를 빠뜨리지 않고 찾아, 입력 조건으로 비교한다.
이 문서는 연구 결과를 반영한 구현 명세 초안이며 운영 서비스의 구현 완료 보고가 아니다.

수집처 등록
LH / SH 주택임대 / GH 청약센터 임대 / GH 청약센터 매입임대 /
GH 본사 분양·임대 게시판 / 서울 청년안심주택 / 청약홈 임대 유형.
기관 하나에 게시판이 여러 개일 수 있으므로 수집 단위는 기관이 아닌 게시판·조회 경로다.
지원 지역, 유형, 기간 제한, 페이지 방식, 마지막 성공 시각, 검증 범위를 함께 기록한다.
민간임대는 위 수집처에 게시된 범위이며, 개별 사업자 사이트의 모든 공고를 뜻하지 않는다.

보존할 데이터
source_post: 출처, 게시판, 원문 ID, 제목, 목록 게시일, URL, 최초·최근 관찰 시각.
snapshot: 요청 조건, 수집 시각, HTTP 결과, 원문 응답, 전체 해시, 핵심 내용 해시.
attachment_version: 첨부 ID/URL, 원래 파일명, 파일 역할, 파일 해시, 보관 위치.
recruitment_round: 독립적인 모집 회차, 공급 유형, 모집 기준일, 신청 기간과 시간대.
relationship: 원본-정정, 재게시, 추가모집, 마감안내 등의 관계와 그 판단 근거.
review_item: 정보 충돌, 원문 누락, 날짜 공란, 추출 실패, 관계 미확정 항목.

동일성·중복 규칙
1. 게시물의 기본 식별자는 출처+게시판+원문 ID다. 제목을 고유키로 사용하지 않는다.
   LH는 연결 시스템 코드와 공고 ID, SH는 실제 게시판 코드와 seq도 함께 보존한다.
2. 같은 ID를 반복 수집하면 게시물을 새로 만들지 않고 관찰 시각 및 버전을 기록한다.
3. 다른 ID에서 제목이 같아도 자동 합치지 않는다. 모집일·회차·공급 대상이 다르면
   별도 모집이며, 필요하면 관련 모집 관계를 둔다.
4. 기관 간 재게시 후보는 주관 기관, 사업·단지, 회차, 모집 기준일, 공고번호,
   주 공고문 파일 등을 함께 확인한다. 공통 신청서가 같다는 이유로 합치지 않는다.
5. 공식 원본·최신 공고 ID, 본문 참조, 명시적 정정 사유는 강한 관계 근거다.
   제목 유사도만으로 확인된 관계처럼 표시하지 않는다.

수정·정정·종료 규칙
1. 원본과 정정 문서를 보존하고 유효한 버전을 별도로 지정한다.
2. 같은 게시물의 첨부파일 변경도 확인한다. 새 게시일이 생긴다고 가정하지 않는다.
3. 파일 해시 변화는 검토 신호다. 문서 내용 변화인지 메타데이터 변화인지 구분한다.
4. 공급 주체의 명시적 정정본을 우선할 수 있지만, 게시 시각만으로 우선순위를 정하지 않는다.
5. 변경된 조건에 의존한 기존 자격 판단은 재검증 대상으로 돌린다.
6. 추가모집은 기존 모집을 지우거나 덮어쓰지 않는다. 독립 일정과 물량을 가진다.
7. 마감·취소 안내는 관련 모집과 연결될 때 상태에 반영한다. 관련 모집을 확정하지
   못한 안내는 검토 대기열로 보낸다. 단순 검색 결과 부재는 취소 근거가 아니다.
8. 실물 파일을 받지 못했거나 핵심 정보가 충돌하면 '확인 필요' 상태를 유지한다.

누락 방지 규칙
1. 신규 게시물 수집: 날짜·유형·상태 필터를 명시하고 검색 결과의 모든 페이지를 확인한다.
2. 현재 진행 중·상시모집 수집: 게시일이 오래돼도 포함하도록 별도 조회·관리한다.
   최근 N일 조회만으로 현재 모집 목록을 만들지 않는다.
3. 진행 공고 재확인: 새 글이 없어도 기존 상세·첨부·관련 정정·종료 안내를 다시 확인한다.
4. 목록 이동 대응: 경계 페이지를 겹쳐 읽고 ID로 중복 제거한다. 조회 중 새 글이
   들어왔는지 첫 페이지와 검색 총건수를 다시 확인한다. 변화 시 영향을 받는 범위를 재조회한다.
5. 게시판에 따라 고정글·날짜 역전이 있으면 첫 과거 날짜 한 건을 보고 중단하지 않는다.
   이번 날짜 경계 검증은 관찰된 정렬에 대한 점검이며 영구적인 정렬 보장이 아니다.
6. 보조 게시판: 원 공고 외의 정정·마감 알림을 포함한다. GH 본사 '기타'가 실제 사례다.
7. 전체 HTML 해시에는 조회수·메뉴 등이 섞일 수 있다. 핵심 내용과 첨부를 별도로 비교한다.

오류와 0건 처리
HTTP 200만으로 정상으로 판정하지 않는다. 예상 목록/상세 구조와 핵심 필드를 검사한다.
정상 필터·목록 구조·명시적 빈 상태가 있어야 '검색 결과 0건'으로 인정한다.
타임아웃, 차단, 파서 실패 시 기존 공고를 삭제하거나 접수마감으로 바꾸지 않는다.
사용자 화면에는 해당 출처의 마지막 정상 갱신 시각을 유지한다.
원문 날짜가 비어 있으면 미확인으로 둔다. 날짜·요일이 충돌하면 임의로 보정하지 않는다.

모니터링 지표
출처별 조회 성공, 마지막 성공 시각, 목록 대비 수집 ID 수, 첨부 다운로드 성공,
해석 대기 공고 수, 변경 검토 대기 수, 원본을 찾지 못한 정정·추가모집 수.
지표에서 모집 게시물, 결과 발표, 종료 안내, 자격 판단 가능한 공고를 구분한다.
'전체 공고 100% 수집'은 분모가 확인되지 않는 한 표시하지 않는다.

LH·청약홈 인증 API 정상 호출 및 웹 목록과의 대조.

운영할 갱신 주기와 수집처별 요청 제약 확인, 자동 처리와 운영 검토의 분담.
주 공고문·별첨의 일정과 자격 조건 추출 정확성 평가.
