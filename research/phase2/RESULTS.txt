ZipFit 2차 검증 — 누락·중복·정정 처리
검증일: 2026-10-01 / 비교 기간: 게시일 기준 2026-09-01~09-30

결론
표본을 다운로드하는 것에서 나아가, 기간별 목록 대조와 실제 변경 사례를
확인했다. GH 본사 게시판을 추가 수집처로 포함해야 하며, 공고의 기관·ID,
모집 회차, 문서 버전, 게시 출처를 구분하는 설계가 필요하다.
검증 코드는 연구용이다. 상시 수집 서비스나 자격 판단 기능을 구현한 것은 아니다.

1. 기간별 목록 점검
LH: 전체 상태·9월 게시일 조건의 화면 표시 172건과 추출한 고유 ID 172개 일치.
    100건+72건의 모든 검색 결과 페이지를 조회했고 날짜 조건도 확인했다.
SH: 6페이지를 조회해 8월 말 경계를 확인. 9월 게시물 50개.
서울 청년안심주택: 4페이지를 조회해 8월 경계를 확인. 9월 게시물 32개.
청약홈: 9월 공공지원민간임대 5개, 일반 민간임대 0개.
        주택 유형과 월 필터가 실제 선택됐는지 확인했으며, 0건은 공식 화면의
        명시적인 빈 결과였다. 수집 실패를 0건으로 치환하지 않았다.
GH 청약센터: 임대·매입임대 두 게시판 첫 페이지의 최신 공고일이 8월이었다.
           점검한 두 목록에서 9월 게시물은 관찰되지 않았다.
GH 본사 게시판: 2페이지에서 8월 경계까지 확인. 9월 게시물 12개.
              이 중 토지·상가·산업시설 등을 제외하면 주거 관련 접수마감 안내를 확인.

숫자는 게시물 수다. 모집 회차, 신청 가능한 공고 수, 공급 주택 수와 다르다.
LH는 선택한 검색조건의 총건수를 대조했고, SH·서울·GH 본사는 날짜순 목록의
경계까지 연속 조회했다. 독립적인 전체 원장이 없으므로 전국 누락률이나 모든
공고의 완전성을 입증했다고 해석할 수 없다.
LH·SH·서울 첫 페이지를 수집 후 다시 조회해 핵심 목록 값이 유지되는지도 확인했다.

2. 확인된 실제 사례

오래전에 게시된 접수 중 공고
- LH '수시모집' 검색에서 2월·3월 게시, 12월 31일 마감으로 표시된 접수 중
  전세임대 공고 4개를 확인했다. 청년, 신혼·신생아 I·II, 다자녀 공고다.
- 최근 한두 달 게시물만 검색해서 현재 신청 가능한 공고를 구성하면 누락된다.
- 대응: 신규 공고 수집과 진행 중·상시모집 재확인을 별도 작업으로 설계한다.

새 글에 밀린 기존 글
- 이전 검증의 서울 청년안심주택 첫 페이지와 이번 응답을 비교했을 때,
  새 글 6개가 들어오고 기존 6개가 첫 페이지에서 사라졌다.
- 사라진 기존 6개는 이번에 조회한 다음 페이지들에서 모두 확인됐다.
- 대응: 첫 페이지나 한 번의 목록에서 사라진 것을 취소·삭제로 처리하지 않는다.

제목이 같아도 서로 다른 모집 회차
- GH 게시물 803(2026-07-07)과 812(2026-08-21)는 제목이 같지만 공고 ID와
  게시일이 다르고 상세 첨부문서도 각 모집일을 표시한다.
- 대응: 제목 중복 제거 금지. 각각의 모집 회차를 보존하고 관련 모집으로 연결한다.

원본과 정정 공고의 명시적 연결
- LH 원주무실1 원본 ID 2015122300020739와 정정 ID 2015122300020792 확인.
- 원본 화면의 최신 공고 ID와 정정 화면의 원본 공고 ID가 서로 연결된다.
- 대응: 제목 유사도보다 공식 관계 ID를 우선하고 원본·정정 이력을 함께 보존한다.
- 실제 취소 공고 사례는 이번 9월 LH 표본에서 찾지 못했다. 취소 처리 규칙은
  설계 항목으로 남기고, 실제 취소 상황까지 검증했다고 표시하지 않는다.

같은 모집공고의 출처별 문서 버전 차이
- 서울 청년안심주택 게시물 6624와 SH 게시물 309925는 2026년 2차 공공임대
  모집공고이며 기준일은 모두 2026-07-31이다.
- 서울시 게시본 PDF는 공급현황 581세대, SH 정정본은 595세대였다.
- PDF의 인쇄 페이지 7을 모두 렌더링해 직접 대조했으며 신규공급도
  349세대에서 363세대로 다르다. SH 본문은 물량 정정 후 재게시했다고 명시한다.
- 두 파일 모두 68쪽이지만 파일 해시와 추출 텍스트는 다르다.
- 텍스트 추출에서는 정정본의 '595' 일부가 누락돼 '55'로 읽혔다.
  따라서 파일 다운로드·텍스트 추출 성공과 숫자 정확성은 별도로 검증해야 한다.
- 이 사례는 두 출처의 현재 문서 버전을 비교한 것이다. SH가 바로 이번 검증
  도중에 파일을 수정했다는 시간적 사실을 확인한 것은 아니다.
- 대응: 하나의 모집으로 묶되 출처와 파일 버전을 모두 보존한다. 명시적으로
  정정된 모집 주체의 원문을 우선하며, 충돌이 남으면 운영 검토 대상으로 둔다.

청약센터 밖의 마감 안내
- GH 본사 '분양/임대 공고' 게시판의 '기타' 분류에서
  '2026년 기존주택전세임대 상시모집 접수마감 안내'(2026-09-21)를 확인했다.
- 본문은 2026-09-23 신청분까지 접수한다고 안내한다.
- GH 청약센터의 두 게시판만으로는 이 안내를 확보하지 못한다.
- 대응: GH 본사 게시판을 추가하고, '주택' 분류만 선택해 수집하지 않는다.
  모집 종료·정정 안내도 원래 모집과 연결할 수 있도록 수집한다.

3. 검증과 저장물
- audit.py로 저장된 실제 응답을 대상으로 19개 확인 항목 통과.
  목록 총건수, 날짜 경계, 페이지 간 중복 ID, 첫 페이지 재조회, 유효한 0건,
  HTTP 200 오류 화면 거부, 오래된 접수 중 공고, 공식 정정 연결 등을 확인.
- 제목 분류는 검토를 돕는 후보 분류다. 분류 성능이나 자격 정확도 평가가 아니다.
- 기존 증거는 덮어쓰지 않고 phase2/evidence에 새 요청 ID로 보존했다.

audit-results.json : 집계·체크 결과·사례 관계·한계
audit-records.json : 페이지별 게시물과 원문 링크
pdf-comparison.json : 두 출처 PDF의 추출 텍스트 차이(시각적 판단과 구분)
COLLECTION_SPEC.txt : 이번 결과를 반영한 수집 설계 초안
requests-01~05.json : 실제 요청 주소 및 검색 조건

재검증(네트워크 요청 없음)
uv run --no-project --with beautifulsoup4 --with lxml --with pypdf python research/phase2/audit.py
